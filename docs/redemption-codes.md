# 兑换码第一版

## 已确认规则

- 「我的」中新增「兑换码」，位于「我的优惠券」和「联系客服」之间。
- 一批选择一种奖励：解读卡或优惠券，每个码发放该批指定的张数或面额。
- 一码全局仅兑换一次。本人重复提交返回原兑换结果，不重复发放；其他账户不能再次兑换。
- 码自生成起一个自然月内有效，按北京时间下个月同日同一时间计算；月末没有同日时取最后一天。
- 兑换的解读卡无使用期限。优惠券自兑换成功起 7 天有效，独立于每周券及退款赠券。
- 每单一张券，不叠加；按先到期优先选券。超过商品金额的部分不结转，最低实付 0.01 元。

## 后台操作

独立管理员登录 `/admin` →「兑换码管理」。填写批次名称、奖励种类、每码奖励及数量后生成。
一次最多 1000 个；每码 1–100 张解读卡，或 0.01–1000 元优惠券。

明码仅本次生成响应提供，必须立即导出 CSV 并妥善保管。页面关闭后不能再次查询完整码。
数据库仅保存摘要及尾号；不在日志、浏览器存储中保存明码。若响应丢失，先核对批次，再停用该批未领取的码；不要直接再点生成。
列表支持批次、状态筛选和分页，记录生成操作者、兑换账户及时间。未兑换且未过期的码可停用，停用不可恢复。

## 实现与验证

- 新增迁移 `20261102_0008`：兑换批次、兑换码、尝试记录；券表增加面额和来源码。
- 老券面额默认 5000 分，保留旧券、订单、退款赠券和卡账本，不重发任何已有权益。
- 兑换与账户余额/账本同事务；用户行锁、兑换码行锁和条件更新防止重复领取及余额竞态。
- 兑换失败不占用码；每账户每分钟最多 5 次、每小时最多 30 次尝试。
- 管理操作必须管理员会话及同源请求；普通账户不能生成/停用码。相关响应 no-store。
- 报告管理仍只读；兑换码管理是新增的管理员写入能力，使用应用数据库连接。

本地预览仅模拟支付与合成账户。部署前须在专用 MySQL 测试库升级到 head，执行
`tests/test_redemptions_mysql.py` 的并发测试，及原支付/退款测试；不得指向正式库。
正式发布需要数据库备份、迁移、API/前端更新。只读管理员数据库账号不需要新增写权限。
本功能不修改新购暂停、测试账户限制、支付和退款开关，也不请求微信支付或模型接口。
兑换记录与赠送账本须保留；回退代码时不要删除新表或已发奖励。
