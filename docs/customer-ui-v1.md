# Customer UI 0.4.0

The customer app uses hash navigation: `#/measure`, `#/reports`, `#/me`,
`#/chart`, `#/report/<job_id>`, `#/cards`, `#/coupon`,
`#/service`, and `#/privacy`. `/admin` remains an independent application.
Hash routes work with the existing Nginx SPA fallback and preserve browser Back.

## Pages and behavior

- Measure: compact name/gender/time/location form, free charting, report shortcut,
  and an honest empty review section with a feedback contact. No invented reviews,
  usage counts, product introductions, matchmaking, or auspicious-date products.
- Reports: guest, loading, error, empty, search, and populated states; current
  account reports only. Cards include four pillars from existing stored snapshots.
  Public report views omit overall percentage, completed-section counts and IDs.
  The endpoint still applies its existing maximum/default history limit.
- Report detail: an eight-topic directory, readable saved drafts, background
  section status, and a chart/reading switch. Cancellation and analysis-only
  deletion controls are removed; full birth-record deletion is in the report list.
  No model names, length warnings, character counts, retry counters or retry buttons.
- My account: default/authorized avatar and nickname, card
  balance, weekly coupon, purchases, order records, QQ contact, privacy/service
  description and logout. Missing/unavailable balances are shown as unknown,
  rather than fabricated zeroes. Live payments remain disabled until separately
  tested and enabled.
- Birth form stays mounted during in-app tab navigation. A one-hour draft is stored
  only in browser sessionStorage so a payment-page reload can continue after explicit
  card use. Logout clears the draft, local report pointer and visible account
  report contents. Free basic charts are now saved to authenticated accounts;
  see [Free chart history](free-chart-history.md) for the current flow and APIs.
- New full reports require an explicit card-use action on checkout. No order/payment is initiated
  by merely opening any tab. Existing backend deduplication and card accounting
  remain authoritative. A readable report is never re-generated by opening it.

## WeChat profile authorization

The existing backend already supports `snsapi_userinfo`, exchanges OAuth code on
the server, requests `/sns/userinfo`, and stores returned nickname/headimgurl.
Deployment changes only `BAZI_WECHAT_OAUTH_SCOPE` in the existing private app env.
AppID, secrets, merchant settings and user identities are not replaced.

Existing sessions do not acquire profile data from a refresh. On My account, use
“授权更新微信头像昵称” to authorize again. A phone WeChat end-to-end test is still
required; local mock login cannot prove the real profile permissions/UX. Display
only the actual shared data from WeChat, with a default avatar/name fallback.

## Visuals and assets

The user-supplied plum image is encoded as WebP at its original 1440x2560 size in
`frontend/src/assets/` and emitted as a hashed asset by Vite. Ivory cards and vermilion controls sit on a
faded paper/plum background; the main reading area uses an opaque paper card.
No external fonts, scripts, profile assets beyond the authorized WeChat avatar,
or image hosts are needed for the theme. The original PNG is retained locally;
the served WebP is about 337 KB instead of 5.4 MB and is shared/cacheable across
all customer pages. The background position and dimensions are unchanged.

## Deployment

Long reports keep their inline directory and add floating directory/top controls
once that directory scrolls out of view. The sheet supports focus containment,
Escape dismissal, and jumps within the current report URL. Controls are hidden
on the basic-chart tab. Reduced-motion preferences are respected.

Customer report details provide no task-cancellation or analysis-only deletion
actions. The report list places a delete action beside each view button; it asks
for confirmation and targets that row's chart ID, removing all reports tied to
the deleted birth record while retaining unrelated reports and order ledgers.

Customer API 401 responses clear the current profile, wallets, history and
visible report content, stop polling, and offer a login action returning to the
same route. The report pointer and submitted birth draft remain available for
explicit recovery. A late response cannot restore the expired profile or open a
payment cashier. Non-authentication errors keep the login state and allow retry.
Account loading uses placeholders instead of false empty/disabled states.

Use the incremental customer-ui-update bundle after the successful payment,
quality, and admin V1 deployment. It checks source hashes, preserves private
configuration and old assets, and backs up source/env/frontend/API image. It
rebuilds/recreates the API only, retaining all three worker containers and the
admin/payment Compose overrides. It adds no database tables or migrations and
makes no model/payment requests or report-data writes. The API restart expires
in-memory admin login sessions; administrators should log in again.

The installer accepts no arguments for read-only preflight, or `--apply` to
deploy. On a stopped stage, keep its printed backup and diagnose before repeating.
If CDN serves the old UI, refresh `/` and `/index.html` in the CDN console.
The release version is 0.4.0; the underlying chart ruleset version is unchanged.

## Plum wheel refinement

Date/time uses five native-scroll snap wheels for Gregorian year/month/day/hour/minute;
location uses linked province/city wheels populated by the existing APIs. Changes
remain drafts until confirmation. Cancel/Escape/backdrop and leaving the measure
page dismiss the sheet without committing. The wheel commit flush prevents a rapid
confirmation from saving the previously selected row. Changing province invalidates
the old city immediately; stale city responses cannot overwrite the active selection.
Leap-day/month lengths are clamped as before. Gregorian/lunar switching uses month boundaries generated from pinned lunar-python 1.4.8.
Leap months have negative month identifiers, explicit labels and valid month lengths.
The submitted ChartRequest remains Gregorian local wall time; hour/minute are preserved.
Switching calendar preserves the same date; the visible trigger remembers the confirmed
calendar while mounted. Supported Gregorian dates remain 1901-01-01 through 2100-12-31,
including their lunar year 1900 boundary. No unknown-hour semantics were added.
The birth form disclosure details were removed; the required consent now links to the
existing privacy/service page. Keyboard arrows, Home/End and PageUp/PageDown are supported.

## Chart reading button and report refinements

Lunar month labels use 十一月 and 十二月, without changing month values or conversion.
Customer report lists and section headers omit completed badges; other states remain
visible and admin statuses are unchanged. The service notice uses the revised
traditional-culture reference paragraph.
The full-reading CTA is a normal card above the chart. It scrolls with the page
and opens the package/payment page directly; there is no unlock confirmation modal,
scroll-triggered floating button or automatic report submission.

## Shared chart and detailed-reading layout

Both new free charts and saved reports use the same content switch, ordered
基础命盘 then 详细解读. A new chart opens its basic chart first; the other tab
shows eight content-introduction cards with all 54 requested topics. These are
static service scope, not personalized report text, generated analysis or a
saved report. Opening a saved report continues to show its own reading content.
Free-chart and saved-report tab states are separate to prevent old report text
from appearing in a new chart preview. Switching tabs or browsing the preview
makes no report/order requests and does not charge cards. Explicit card use on checkout, server authorization and card entitlement logic stay
in place. Topic titles are shared with pending-section placeholders; generation
prompts and all existing report data are unchanged.

Preview topic cards use decorative blurred line layers behind crisp scope labels,
with a lock badge and a full-report unlock action. The blur contains no personal
report content. All eight preview unlock actions use the same entitlement flow;
one card covers the whole eight-section report, not one payment per section.
Saved personal reading content is outside these styles and remains unblurred.

## Unlock from detailed reading

The basic-chart upsell panel and checkout's continuation panel are removed.
The eight locked previews retain the explicit unlock action. For a logged-in
account with payments enabled, this submits the current chart's unlock request;
the server checks ownership, existing reports and card balance atomically.
Insufficient cards preserve the chart draft and open #/cards. Guests or disabled
payments go to checkout without submitting an analysis request.

Checkout only purchases cards: it does not offer a start-reading callback or
show remaining cards. Payment confirmation still refreshes account data, but
never starts a report. Users return to their saved report and unlock from
Detailed Reading. Card balance remains visible in My Account. The existing
submission lock, server deduplication and deletion confirmation are retained.

## Compact checkout packages

Checkout removes the requested long service, cancellation, password-safety,
card-use and weekly-coupon schedule copy. Service details remain available in the service page; coupon status and expiry
remain available in the coupon page. The checkout footer tagline is removed.
Package cards show name and card quantity on the left, actual payable price
on the right and a full-width selection button below. Coupon calculations,
order confirmation, payment handling and refund contact details are unchanged.

## Coupon copy and manual order-query removal

The coupon page is titled 解读优惠券 and keeps status and expiry without the
北京时间 prefix. The expiry still formats in Asia/Shanghai. Detailed weekly
issuance/usage rule paragraphs are removed from this view only; actual coupon
issuance, expiry and discount rules are unchanged. The pending-order 查单 button
and its dedicated manual-query branch are removed. Closing uses its own action.
Post-cashier automatic reconciliation, signature checks, webhook handling and
server-side idempotent card crediting continue to operate as before. Prompts no
longer direct users to a removed query button.

## Available coupons only

The coupon detail page renders an amount/expiry card only for an available
coupon. Used, reserved or absent coupons show 暂无可用优惠券 without a face
value, expiry or used-status label. Guest, loading, disabled-service and request
error states stay distinct from an empty wallet; a request failure offers retry.
This is display logic only and does not modify any coupon issuance or accounting.

## Profile and coupon empty-state refinement

The customer profile no longer renders the internal user ID, copy-ID control or
copy-feedback logic. The coupon asset fallback reads 优惠券 without the used
status subtitle; usable amount/status and other account states remain truthful.
Support asks for the chart name and screenshot instead of an ID customers can
no longer see. Empty coupon view has only 暂无可用优惠券, without an emblem.
Internal account IDs, report ownership and authentication are unchanged.

The standalone manual-refund explanation block is removed from checkout.
Refund contact information in purchase records and customer service remains available.

The measure form starts directly with its fields, without the visible 填写生辰
heading or local-clock instruction. An accessible offscreen 出生资料 heading
labels the form section. Date-picker instructions and input semantics are unchanged.

Expanded major-luck cycle ranges use 年月日 dates only, without leading-zero
months/days or time of day. Display conversion still uses Asia/Shanghai; stored
instants, chart calculations, true-solar time and luck-start timestamps are unchanged.

## Four-pillar matrix

Basic chart and saved-report chart views now use a five-column semantic table:
row label then year/month/day/hour. Rows align main star, stem, branch, hidden
stems, secondary stars, star fortune, self seat, void, na-yin and shen-sha.
Hidden stems, stars and shen-sha render in full as vertical lists per pillar.
Five-element colors are presentation metadata only; stem/branch icons are removed. All chart facts still
come from existing API snapshots. All four columns remain visible at 320px.
The prior separate pillar cards are replaced; luck cycles and dates are unchanged.

## Horizontal major-luck and annual-year timeline

The old overview and accordion list are replaced by a compact start-date header,
a horizontally scrollable major-cycle strip and a linked annual-year strip.
Selecting a cycle swaps in its exact API annual_years array (including partial
Lichun boundary years); selecting a year updates the always-visible details. Selected
columns are highlighted; 今 restores the current date-based cycle/year and
recenters both strips horizontally without moving the page vertically. Start/end
intervals are half-open instants and date-only labels use Asia/Shanghai. Current
stage selection falls back to the first/last available cycle before/after the
provided range. Empty arrays have explicit empty states.
Existing stem ten-gods and cycle primary hidden-stem stars appear as short red
labels; full values, na-yin and complete shen-sha remain in always-visible details.
The cycle heading combines its name, year range and age range; the annual heading
uses name, year and age. Annual Lichun date ranges are no longer displayed.
Annual branch stars are enriched by the existing backend hidden-stem rules for
both free charts and saved reports, without changing stored snapshots or debit
identity. Missing minor-luck/司令 fields are not invented. Model prompts and payment
rules are unchanged.

The customer purchase-history menu, #/orders page, copy-order controls and
manual balance/coupon refresh button are removed. Checkout retains pending-order
payment/close actions, post-payment reloads and background account refresh.
Server order records and payment/refund bookkeeping are retained.

Checkout no longer renders coupon status/checkbox controls. An available coupon
is always applied to displayed package prices and use_coupon on order creation.
Used/reserved/absent coupons do not apply, so original prices and use_coupon=false
are used. The backend remains authoritative for actual eligibility and amounts.
